Fixed upstream

Bugs in open-source payment code where a payment ends in the wrong state: the customer is charged and gets no order, or the webhook is acknowledged and the provider stops retrying. Each was reproduced against the project's own code before it was reported, with a test in the project's suite or a harness in callback-audit.

Status as of 20 October 2026.

Fixed (8)

  • Bagisto · Razorpay: the order amount was truncated instead of rounded, so totals like ₹19.99 were charged but no order was placed. Fixed by my PR, merged 13 Oct. #11523 · PR #11524
  • Paid Memberships Pro · Stripe: the webhook answered 200 when re-fetching the event from Stripe failed, so Stripe never redelivered it. Fixed by my PRs, merged 14 and 15 Oct; the second covers scheduled webhook runs. #3889 · PR #3890 · PR #3898
  • FOSSBilling · Stripe: subscription renewals were never recorded after the first invoice, so Stripe charged the customer and the renewal invoice stayed unpaid. Fixed by my PR, merged 16 Oct. #4522 · PR #4523
  • FOSSBilling · Stripe currencies: in COP, HUF, IDR, ISK, PKR, UGX and seven other currencies the total is sent to Stripe in the wrong unit, so the customer is charged 1/100 and the invoice is marked paid. Fixed by my PR, merged 17 Oct. #4540 · PR #4541
  • Bagisto · PayPal Standard: a buyer who paid but didn't return to the store got no order, and every retry of PayPal's notification failed with 500. Fixed by the maintainers on 15 Oct, listed in the changelog. #11531
  • Invoice Ninja · Stripe iDEAL, Bancontact, Klarna: no payment was recorded when the customer didn't come back from the bank. Fixed by the maintainers on 12 Oct. #13341
  • django-payments · Sage Pay: the return route crashed on every real redirect, so no payment was ever confirmed. Fixed by the maintainer on 11 Oct. #499 · PR #500
  • Odoo · Mollie: a failed status request to Mollie was acknowledged with 200, so the transaction stayed in draft. Fixed by Odoo on 8 Oct. #290678 · fix · case

Confirmed, fix in progress (4)

  • Adyen for Magento 2 · split payments: the cause of “Full order amount has not been authorized”: authorised amounts were compared at a different precision than they are stored. Confirmed by the reporter; Adyen opened a ticket and is reviewing my patch. #3352 · PR #3379
  • Mollie for WooCommerce: the REST webhook answers 200 when the payment status can't be fetched, so Mollie stops retrying and paid orders stay pending. Confirmed by Mollie; they are preparing a patch. #1304 · case
  • Medusa · Stripe: the webhook signature is checked when the queued job runs, so a delivery already answered 200 is dropped if the job starts more than five minutes after Stripe signed it. My PR passed Medusa's automated review and waits for the team. #17261 · PR #17262
  • LNbits · fiat payments: a fiat invoice was failed after one hour while the provider's checkout was still payable, so a later payment was never credited. The maintainer agreed on the fix; my PR is updated after review. #4245 · PR #4246

Reported, waiting for the maintainers (17)

  • Pay. for Magento 2: when the plugin's status request to Pay. fails, the payment notification is still answered TRUE, so Pay. never retries it and the paid order is cancelled. #248 · PR #249
  • Checkout.com for WooCommerce: in classic mode a 3-D Secure payment is linked to the order only when the buyer comes back to the shop, so if they don't, every webhook for the captured payment is rejected and the paid order is cancelled. #431
  • PayU for WooCommerce: on the main branch, not yet released, a COMPLETED payment notification is answered 200 but no longer completes the order, so the paid order stays on hold or is cancelled as unpaid. #121 · PR #122
  • Akaunting · PayPal Standard: the payment notification is checked with PayPal using an empty request, so PayPal answers INVALID every time and no PayPal payment is recorded. #8 · PR #9
  • BTCPay for WooCommerce: when the plugin cannot re-fetch a settled invoice from BTCPay Server, the webhook is still answered 200, so BTCPay never redelivers it and the paid order stays on hold. #93
  • Lunar · Stripe: when listing the payment's charges from Stripe fails once, the paid order is not placed and the payment is marked processed, so no retry places it. #2781
  • Payfast for WooCommerce: when the plugin's validation request to Payfast fails, the payment notification is still answered 200, so Payfast never re-sends it and the paid order is cancelled. #519
  • EverShop · Stripe refunds: a refund made in EverShop is recorded a second time when Stripe's refund notification arrives, so the order shows twice the refunded amount and a full refund sends the customer a second email. #1112
  • Paymenter · Stripe SEPA Direct Debit: when a SEPA payment succeeds after the daily cron has cancelled the unpaid order, the service is marked active but the server is never created. #1378 · PR #1381
  • WooCommerce PayPal Payments · iDEAL and other local methods: when the fee lookup after the capture fails, the webhook still answers 200, so the order stays pending and is later cancelled although PayPal captured the payment. #4798 · PR #4799
  • Invoice Ninja · SEPA, BACS, ACH, GoCardless: a subscription whose payment starts as pending is never completed, so no recurring invoice follows. #13343
  • Laravel Cashier Mollie: the webhook answers 200 when fetching the payment from Mollie fails, so a paid first payment never starts the subscription. #330 · PR #331
  • Odoo · Mercado Pago: the webhook answers 200 when fetching the payment from Mercado Pago fails, so it stops retrying. #293901
  • django-paypal: when a receiver raises, PayPal's retry of the same message is flagged as a duplicate and acknowledged, so the payment is never processed. #299
  • django-oscar-paypal: a pending or declined PayPal capture places the order as paid. #302
  • Razorpay for WooCommerce: with the Payment Action set to “Authorize”, the webhook cron marks orders of authorized payments Failed. #670 · case
  • WooCommerce Stripe Gateway: a webhook that fails signature validation is answered 204, so Stripe never retries and the order stays pending. #4150 · case
